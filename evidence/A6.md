## Observed A6 behavior

- Successful worker identity and suspended Job Object setup were followed by the persisted RUNNING state, PID/SID/process creation time and credential hash before resume. The private worker read its selected copy and published one hash-verified output; the task reached COMPLETED after exit and job drain.
- Single-worker admission rejected a second task while the first worker was still active. A later task was admitted after cleanup.
- The fixed denial probe requested an unselected document. SQLite recorded the denial and policy revocation, the credential was revoked, the worker Job Object stopped, and reuse returned HTTP 401. The incident's containment was `terminated`; integrity and confidentiality remained `unknown`, so A6 recorded FAILED rather than claiming BLOCKED. The A7 verifier is still pending.
- Cancellation, timeout and orderly controller shutdown revoked credentials before terminating the worker Job Object. The tests checked each worker and child by retained PID plus process creation time using Windows process handles and wait results; all were stopped. The timeout race preserved a publication that had already passed its authorization lock before timeout, then recorded timeout as the terminal cause. No new effect began after revocation.
- A worker crash with a child returned exit code 23. The controller observed both worker and child stopped before failing the task.
- Cancellation racing process exit produced one lock-ordered outcome; the timeout/completion race held publication at its final database boundary, advanced to the deadline, and verified the authorized output record remained singular while the task failed with WORKER_TIMEOUT.
- Restart recovery used a separately launched controller helper and a real worker/child Job Object. The harness terminated that exact helper process, then independently checked both recorded process identities stopped. A newly opened controller revoked the prior credential, reconciled the task through VERIFYING to FAILED with `RECOVERY_INTERRUPTED`, cleaned only the task workspace, and rejected credential reuse with HTTP 401.
- The test compared the A2 manifest's protected original fixture hashes before and after the lifecycle suite; all matched. Actual PIDs, tokens, task configuration, process captures, databases, and runtime fixtures stayed in temporary or protected locations and were not committed.
- Windows tests now place their database and verified outputs in a per-test temporary root and remove it during teardown. An audit found 71 exact synthetic A6 output directories and one orphaned `a6-race-*` test database from earlier runs; their UUID paths and deterministic probe content were checked before file-by-file removal. The successful rerun left the protected verified-output root empty and no A6 runtime database behind.

Portable deterministic tests also cover preparation failure and admission recovery, publication/denial serialization, cancellation/process-exit arbitration, timeout/completion precedence, database failure containment, monitor-thread startup failure after worker resume, missing durable publication state, and preservation of an already committed revocation cause through restart recovery.
