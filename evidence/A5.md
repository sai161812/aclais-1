# A5 broker and publication evidence

## Scope

A5 implements the credential-bound broker and controller-owned output publication on the existing A2–A4 foundation. This is not a G1 pass. The default FastAPI app still exposes only health; trusted startup assembly must inject the broker, and output downloads additionally require an owner authorizer. A8 supplies real owner authentication. A6 still owns task-directory ACL setup, launcher integration, cleanup and startup recovery.

- `uv run --locked ruff check .` — passed.

They verified selected-copy reads, original-file hashes after denied reads/mutation, strict malformed/forged/oversized requests, credential-to-task binding and expiry, operation/tool validation, persisted events and output records, exact replay, changed-body conflict, one-output-slot uniqueness, concurrent requests, retry from a durable reservation and every later crash boundary after reopening SQLite and constructing new broker/publisher instances, raced collision no-overwrite, tamper withholding and finalization database failure.
